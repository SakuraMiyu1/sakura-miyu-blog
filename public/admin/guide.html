Перший вхід

Потрібне одноразове налаштування GitHub OAuth. Якщо редактор повідомляє, що вхід не налаштовано, відкрий CMS_SETUP.md і виконай розділ налаштування. До цього моменту публікація через CMS вимкнена. Банківська картка й платна підписка не потрібні.

Після налаштування відкрий /admin/ і натисни Login with GitHub. У вікні GitHub увійди саме як SakuraMiyu1 і підтвердь доступ власного OAuth-застосунку. Дозволь спливаюче вікно для цього сайту, якщо браузер його блокує.

Новий запис

  1. Відкрий Diary entries → New Diary entry.
  2. Заповни Title, Description, дату, категорію, теги й мову.
  3. У URL slug введи адресу латиницею, наприклад a-quiet-morning. Для English вона створить /en/blog/a-quiet-morning/. Заповни Translation Key: спільний ключ перекладів, наприклад a-quiet-morning. Не змінюй адресу вже опублікованого запису.
  4. Напиши текст цією мовою у Story. Кнопки над текстом допомагають додавати форматування й зображення. Попередній перегляд показує вміст запису; він не відтворює весь сайт.

Зберегти чернетку

Натисни Save draft. Редактор збереже окрему гілку й pull request у GitHub. Це ще не публікація на основному сайті. Чернетки доступні у Workflow. Не натискай Publish, доки текст не готовий.

Важливо: репозиторій GitHub публічний. Збережені чернетки й завантажені картинки можна прочитати в GitHub, навіть коли їх немає на сайті. Не зберігай там приватні дані. Для конфіденційних нотаток використовуй локальний файл.

Опублікувати

Перевір текст і дату. Перемикач Keep hidden even after Publish має бути вимкнений. Переведи запис у Ready і вибери Publish now у меню Publish. Назви кнопок можуть трохи відрізнятися залежно від розміру екрана. Зміни потраплять у main; Cloudflare автоматично збере сайт. Дочекайся успішного деплою перед перевіркою.

Keep hidden even after Publish — додатковий захист: увімкнений перемикач записує draft: true, тому запис не з'явиться навіть після злиття в main. Майбутня дата також приховує запис; для його появи після настання дати потрібна нова збірка.

Зображення

У Featured image натисни вибір зображення та Upload. Додай Featured image alt text — короткий опис зображення. Для картинки всередині тексту скористайся кнопкою Image й заповни опис. Картинки зберігаються в окремій папці public/images/blog/. Початкові hero, avatar і background не перезаписуються.

Використовуй JPEG, PNG або WebP до 5 MB. Давай файлам унікальні назви латиницею, наприклад 2026-10-17-pink-ribbon-01.jpg; не підтверджуй заміну існуючого файлу випадково. Підтримувані картинки оптимізуються у браузері до ширини 1600 px і WebP. На iPhone краще обирати JPEG, а не HEIC.

Мови

Для кожного перекладу створи окремий запис: вибери Українська (uk), English (en) або 日本語 (ja), заповни перекладені Title, Description і Story. В усіх версіях однієї історії вкажи однаковий Translation Key. URL slug має бути унікальним у вибраній мові; однаковий slug дозволений для різних мов. Редактор збереже окремі файли uk--a-quiet-morning.md, en--a-quiet-morning.md і ja--a-quiet-morning.md. Мову збереженого запису з таким префіксом не змінюй: створи окремий переклад. Текст не перекладається автоматично.

Multilingual залишено лише для редагування старих записів. У них збережи lang та ID ukrainian, english, japanese і порожні рядки навколо HTML. Старі записи без Translation Key можна зберігати без додавання цього поля; за потреби додай ключ, спільний із їхніми перекладами.

Редагування, SEO та видалення

Вибери наявний запис у Diary entries, відредагуй і збережи. Для правок додай Updated date. URL наявного запису зберігається. За потреби заповни SEO title і SEO description; порожні поля використовують основні Title та Description.

Для видалення відкрий меню запису → Delete і прочитай підтвердження. Видалення опублікованого запису прибере його після наступного деплою та зламає його стару адресу. Спочатку краще увімкнути Keep hidden even after Publish, якщо потрібно лише тимчасово приховати запис.

Новий тег можна просто додати у Tags. Категорії фіксовані: для додавання категорії потрібно узгоджено змінити список у src/lib/post-utils.ts та public/admin/config.yml. Звичайні публікації коду не потребують.

На iPhone

Відкрий редактор у Safari, дозволь popup GitHub і використовуй вертикальний режим для полів. Перемикай Edit/Preview замість одночасного перегляду двох колонок. Для довгого тексту зручний горизонтальний режим. Поки Save draft не завершився, не закривай вкладку. На спільному пристрої після роботи натисни Log out у меню профілю.

Якщо CMS недоступний

Увійди в GitHub як SakuraMiyu1. Відкрий папку дописів → Add file → Create new file. Скопіюй шаблон, назви файл my-entry.md, заповни текст і метадані. Для публікації встанови draft: false і підтвердь Commit changes до main. Cloudflare зробить решту. Для чернетки створи окрему гілку або залиш draft: true.

Цей спосіб безкоштовний і працює без CMS, OAuth або локальних npm-команд. Якщо вичерпано безкоштовний ліміт збірок, дочекайся його поновлення; платний план не потрібний.
