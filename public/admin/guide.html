Перший вхід

Потрібне одноразове налаштування GitHub OAuth. Якщо редактор повідомляє, що вхід не налаштовано, відкрий CMS_SETUP.md і виконай розділ налаштування. До цього моменту публікація через CMS вимкнена. Банківська картка й платна підписка не потрібні.

Після налаштування відкрий /admin/ і натисни Login with GitHub. У вікні GitHub увійди саме як SakuraMiyu1 і підтвердь доступ власного OAuth-застосунку. Дозволь спливаюче вікно для цього сайту, якщо браузер його блокує.

Одна стаття — три мовні вкладки

  1. Відкрий Articles → New Article.
  2. У Article ID введи постійну назву латиницею, наприклад a-quiet-morning. Вона збереже одну статтю у файлі src/content/articles/a-quiet-morning.json. Після створення ID не змінюється.
  3. Заповни спільні Publication date, категорію, Tags, зображення та перемикачі видимості.
  4. У вкладках Українська (UA), English (EN) і 日本語 (JP) заповни власні Title, URL slug, Description і Story кожної потрібної мови. Для English slug a-quiet-morning створить /en/blog/a-quiet-morning/. Не змінюй уже опубліковані slug.
  5. Пиши Story звичайним Markdown. Зберігай і публікуй статтю один раз — разом з усіма мовами. Не потрібно створювати три записи.

Зберегти чернетку

Натисни Save draft. Один JSON зі спільними налаштуваннями й усіма перекладами збережеться в одну гілку й pull request GitHub. Повторне Save оновлює ту саму статтю. Це ще не публікація на основному сайті. Чернетки доступні у Workflow.

Важливо: репозиторій GitHub публічний. Збережені чернетки й завантажені картинки можна прочитати в GitHub, навіть коли їх немає на сайті. Не зберігай там приватні дані. Для конфіденційних нотаток використовуй локальний файл.

Опублікувати

Перевір текст і дату. Перемикач Keep hidden even after Publish має бути вимкнений. Переведи статтю у Ready і вибери Publish now один раз. Завершені мовні версії стануть доступними після merge до main й успішної збірки Cloudflare. Назви кнопок можуть трохи відрізнятися залежно від розміру екрана.

Для публікації мовна версія має містити Title, URL slug, Description і Story. Незаповнені та частково написані переклади зберігаються, але не створюють сторінок, результатів пошуку, RSS або посилань перемикача. Обов’язкової основної мови немає. Keep hidden even after Publish приховує одразу всі мови навіть після merge. Майбутня дата також приховує статтю; після її настання потрібна нова збірка.

Зображення

У спільному Featured image натисни вибір зображення та Upload. У кожній завершеній мовній вкладці додай Featured image alt text — короткий опис відповідною мовою. Для картинки всередині тексту скористайся кнопкою Image й заповни опис. Картинки зберігаються в public/images/blog/. Початкові hero, avatar і background не перезаписуються.

Використовуй JPEG, PNG або WebP до 5 MB. Давай файлам унікальні назви латиницею, наприклад 2026-10-17-pink-ribbon-01.jpg; не підтверджуй заміну існуючого файлу випадково. Підтримувані картинки оптимізуються у браузері до ширини 1600 px і WebP. На iPhone краще обирати JPEG, а не HEIC.

Мови

Перемикай вкладки мишкою або клавіатурою: стрілки ліворуч/праворуч, Home та End. Усі тексти залишаються в тій самій статті. Кожна мова може мати власний slug, SEO й опис зображення. Переклади пишеш самостійно — автоматичного перекладу й AI немає.

Теги

Спільні Tags використовуються в усіх мовах. Залиш Language-specific tags у вкладці недоторканим, щоб успадковувати спільні теги. Якщо додаси власний список, він замінить спільний для цієї мови; збережений порожній список означає «без тегів». Категорії фіксовані; нові звичайні теги можна додавати без коду.

Редагування, SEO та приховування

Вибери статтю в Articles, відредагуй потрібні вкладки й збережи один раз. Для правок додай спільну Updated date. За потреби заповни SEO title і SEO description у мовній вкладці; порожні поля використовують її Title та Description.

Видалення через CMS вимкнене. Щоб прибрати статтю з публічного сайту, увімкни Keep hidden even after Publish, збережи та опублікуй зміну. Тексти й медіафайли залишаться в репозиторії. Наявні оригінальні Markdown-файли збережені як архів; редагуй відповідну статтю в Articles, щоб змінити її публічний вміст.

На iPhone

Відкрий редактор у Safari, дозволь popup GitHub і використовуй вертикальний режим для полів. Перемикай Edit/Preview замість одночасного перегляду двох колонок. Для довгого тексту зручний горизонтальний режим. Поки Save draft не завершився, не закривай вкладку. На спільному пристрої після роботи натисни Log out у меню профілю.

Якщо CMS недоступний

Увійди в GitHub як SakuraMiyu1. Відкрий папку статей → Add file → Create new file. Скопіюй JSON-шаблон, назви файл a-little-moment.json та залиш такий самий translationKey. Заповни спільні поля й translations.uk/en/ja. У рядках body використовуй Markdown, \n\n для абзаців та \" для лапок. Для публікації встанови draft: false і підтвердь Commit changes до main. Для чернетки залиш draft: true або створи окрему гілку.

Цей спосіб безкоштовний і працює без CMS, OAuth або локальних npm-команд. Якщо вичерпано безкоштовний ліміт збірок, дочекайся його поновлення; платний план не потрібний.
