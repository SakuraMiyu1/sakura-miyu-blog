# Sakura Miyu Comics

Розділ використовує наявні Astro, TypeScript, локалізацію UA/EN/JA та статичний Cloudflare Pages build. Нових сервісів, залежностей, платіжних даних або платних функцій немає.

## Поточний стан

Публічні маршрути: `/uk/comics/`, `/en/comics/`, `/ja/comics/` і `/{locale}/comics/two-queens-of-the-fog/`.

«Дві королеви Туману» / “Two Queens of the Fog” / 「霧の二人の女王」 — анонс зі статусом Coming Soon та тимчасовою абстрактною обкладинкою. Видимість анонсу задає окремий `announcement: { approved: true, published: true }`; сам комікс залишається `approved: false`, `publicationStatus: "draft"`. Затвердження анонсу не означає затвердження коміксу, випусків або фінальних ілюстрацій. Передісторія `prologue` та `issue-01` також залишені чернетками без сторінок. Вони не мають публічних маршрутів і не входять до sitemap. Статус Completed автоматично не встановлюється.

## Локальна читалка

```sh
npm run dev:comics
```

Відкрий `/uk/comics/reader-demo/prologue/`, `/en/comics/reader-demo/prologue/` або `/ja/comics/reader-demo/prologue/`. Окремий тестовий випуск `/uk/comics/reader-demo/issue-01/` має UA та EN; японський маршрут показує повідомлення про відсутність перекладу. Усі ці сторінки містять явне позначення TEST / LOCAL DEMO і не є матеріалами реального фанкоміксу.

Демо вмикається лише через `COMICS_DEMO=1`. На Cloudflare Pages цей режим заборонений перевіркою build; не додавай цю змінну в Cloudflare. Звичайні `npm run dev` і `npm run build` демо не включають. Тестові ілюстрації створюються статичним endpoint лише в локальному деморежимі; у production їх немає.

## Керування через CMS

Відкрий `/admin/`, увійди чинним GitHub OAuth і вибери **Комікси · Comics · コミック**. Для нової серії натисни **New Comic**, а для наявної — відкрий її запис. Назви, описи, жанри, alt-тексти та назви випусків мають окремі вкладки Українська / English / 日本語. Обкладинка серії та social image завантажуються один раз.

У **Issues** додай випуск, заповни постійні ID/slug, номер, дату й три назви. У **Pages** перемикай мови, додай обкладинку першою, а решту сторінок після неї. Порядок змінюється drag-ручкою; Page ID та порядок мають збігатися у всіх наявних перекладах. Редактор приймає PNG, JPEG, WebP та AVIF до 5 MiB, створює оптимізовані WebP/AVIF reader-копії й не змінює оригінали на пристрої. Поля width/height необов’язкові; якщо вони потрібні, заповни обидва фактичними розмірами готової копії.

Режими даних:

- `Draft` — зберігається в editorial workflow, публічного маршруту немає.
- `Preview` — live preview у CMS, але матеріал не стає публічним.
- `Published` — працює лише разом з окремим `approved: true`; для випуску також потрібна опублікована серія.

Натисни **Save draft**, щоб зберегти один JSON з усіма мовами та медіафайлами в GitHub-гілці чернетки. Перед **Publish now** переглянь preview. Порожній Published-випуск блокується; про відсутню мовну версію CMS попереджає окремо. Медіафайли CMS зберігаються у `src/content/comics-media/` і віддаються сайтом тільки тоді, коли серія та випуск справді схвалені й опубліковані. Оскільки GitHub-репозиторій публічний, приватні матеріали й майстер-файли високої роздільності там зберігати не можна.

Для «Двох королев Туману» залишай `coming-soon`, `approved: false` та `publicationStatus: "draft"`, доки власниця окремо не затвердить серію. Передісторія й `issue-01` теж мають залишатися чернетками. Анонс керується окремо й не публікує випуски.

## Ручне додавання наступного випуску (резервний спосіб)

1. Отримай підтвердження власниці проєкту на конкретний випуск і кожну підготовлену мовну версію. Повідомлення про фанатський контент не замінює дозволу правовласника і не доводить юридичну допустимість публікації.
2. Редагуй відповідний JSON у `src/data/comics/`. Для нової серії створи новий JSON із такою самою структурою: loader підхоплює файли автоматично. `id` та `slug` мають бути унікальними й незмінними після публікації.
3. Додай об'єкт у `chapters`: постійні `id` і `slug`, унікальний `order`, заголовки `titles.uk/en/ja`, `approved`, `publicationStatus` та `pages`. Поки випуск не затверджений, використовуй `approved: false` і `publicationStatus: "draft"`. Порожні сторінки допустимі для чернетки.
4. Після затвердження підготуй окремі оптимізовані WebP/AVIF для кожної доступної мови. Рекомендована ширина — 1200–1600 px. Перевірка обмежує ширину 2000 px, висоту 5000 px і файл 5 MiB. Оригінали високої роздільності тримай **поза публічним GitHub-репозиторієм**, не лише поза `public/`.
5. Reader-копії затвердженого випуску розмісти в `public/images/comics/{comic-id}/{chapter-id}/{locale}/`. У кожної сторінки вкажи стабільний `id`, `kind`, `src`, фактичні `width`/`height` та змістовний `alt` відповідною мовою. Обкладинка йде першою з `kind: "cover"`, далі — `kind: "page"`.
6. У перекладів повинні збігатися ID та порядок сторінок. Японська версія не розвертається. Не підмінюй відсутній переклад українськими ілюстраціями: залиш відповідний масив відсутнім або порожнім. Доступність мови та кількість випусків визначаються з затверджених непорожніх масивів `pages`.
7. Лише після затвердження встанови і для самого коміксу, і для випуску `approved: true`, `publicationStatus: "published"`. Сам прапорець анонсу не відкриває читалку або сторінки випусків. За потреби вручну зміни статус серії з `coming-soon` на `ongoing`; `completed` — лише після підтвердження завершення.
8. Запусти перевірки нижче та переглянь локальну версію. Коли розгортання схвалено, використовуй наявний GitHub → Cloudflare Pages workflow: `npm run build`, output `dist`, без нових обов'язкових environment variables.

Приклад елемента `pages.uk` для вже затвердженого випуску:

```json
[
  { "id": "cover", "kind": "cover", "src": "/images/comics/two-queens-of-the-fog/issue-01/uk/cover.webp", "width": 1200, "height": 1600, "alt": "Українська обкладинка випуску 1; опиши затверджений малюнок" },
  { "id": "page-01", "kind": "page", "src": "/images/comics/two-queens-of-the-fog/issue-01/uk/page-01.webp", "width": 1200, "height": 1600, "alt": "Змістовний опис першої сторінки українською" }
]
```

Маршрути читалки створюються автоматично: `/{locale}/comics/{comic-slug}/{chapter-slug}/`. Немає потреби змінювати код читалки. Після додавання JSON або випуску перезапусти dev-сервер або виконай build, щоб оновити статичні маршрути. Для затвердженого випуску створюються три мовні маршрути, але відсутній переклад показує повідомлення з `noindex`; у sitemap та SEO hreflang потрапляють лише доступні версії. Чернетки не отримують маршрутів. Перевірка `verify-comics` забороняє неопубліковані та зайві файли у `public/images/comics/`, щоб випадкове копіювання чернетки не зробило її загальнодоступною.

## Читання

Кнопки Previous/Next та стрілки клавіатури перегортають сторінки. Покажчик дозволяє перейти одразу до потрібної сторінки. Прогрес зберігається локально за ID коміксу та випуску, без облікового запису або зовнішнього сервісу. Явний `#comic-page-01` у посиланні має пріоритет перед збереженим прогресом. Перемикання мови через меню або кнопки читалки зберігає той самий випуск та ID сторінки. Масштаб 100–200% прокручується всередині області читання; системний pinch/browser zoom доступний завжди.

Без JavaScript усі сторінки відображаються послідовно; є звичайні посилання-покажчики. Посторінковий режим, автоматичне перенесення позиції між мовами, кнопки масштабу та localStorage потребують JavaScript. Блокування або очищення localStorage не ламає читалку.

Кнопок Download, PDF та архівів немає. Абсолютного захисту від копіювання немає: доступне браузеру зображення технічно можна зберегти. Фанкомікс не має платного доступу, продажу, підписок чи пов'язаних донатів. Повідомлення про неофіційний, некомерційний та створений із допомогою генеративного ШІ контент показується трьома мовами.

## Перевірка

```sh
npm test
npm run build
npm run test:comics
```

`test:comics` перевіряє production output, потім збирає ізольований локальний demo build у `.qa-dist/comics` і перевіряє читалку в браузері. Потрібен доступний Playwright Chromium; на цьому Windows-комп'ютері можна використати встановлений Edge через `TEST_BROWSER_CHANNEL=msedge`. Новий браузер автоматично не встановлюється. Реальні дані коміксів, статті та медіафайли не змінюються. Скріншоти зберігаються в ігнорованому `test-results/comics/`.

Щоб повторно згенерувати лише власну тимчасову обкладинку-анонс: `node scripts/prepare-comic-cover.mjs`. Це не створює ілюстрацій або випусків фанкоміксу.
